# GlyphLock — Prototype 0

A private Android live-wallpaper experiment in which high-density glyph artwork transforms into concise, event-shaped information.

**This repository intentionally contains no Hermes integration, no connectors, no network client, no microphone permission, and no account permissions.** Prototype 0 exists to answer the visual question first: _is the transformation beautiful enough to deserve a permanent place on the lock screen?_

## What is implemented

- Three original procedural glyph scenes: **Sentinel**, **Moth**, and **Orbit**.
- Three local demo events: important email, calendar collision, and recovered deployment.
- Artwork-to-information morphing rather than notification cards over a wallpaper.
- Android `WallpaperService` implementation.
- Full-screen Android preview using the same scene renderer.
- Tap, long-hold, horizontal swipe, and upward-collapse interaction grammar.
- Simulated listening and simulated result states.
- Browser visual laboratory for fast composition work.
- Local-only immutable fixtures; the app requests no runtime permissions.

## Product boundary

Prototype 0 is deliberately narrow:

```text
LOCAL DEMO EVENT
      ↓
SEMANTIC VISUAL STATE
      ↓
GLYPH SCENE + TEXT GEOMETRY
      ↓
LIVE WALLPAPER / PREVIEW
```

Hermes will be introduced only after the visual gate passes. No placeholder agent SDK has been added, so the rendering architecture cannot quietly become coupled to a backend before it is ready.

## Android interaction

- **Wallpaper becomes visible:** optional automatic reveal of the selected fixture.
- **Tap lower area:** reveal/focus the current event.
- **Hold lower area:** simulate event-bound voice interaction, then show a local result.
- **Swipe left/right:** change fixture event.
- **Swipe up:** return the information to the artwork.

Wallpaper touch delivery varies by launcher and OEM. The interactive preview is the reliable evaluation surface; the wallpaper uses the same best-effort gestures.

## Run the visual laboratory

```bash
python3 -m pip install -r scripts/requirements.txt
python3 scripts/generate_scene_masks.py
cd apps/visual-lab
npm install
npm run build
npm run serve
```

Open `http://localhost:4173`.

Create a single-file interactive build with:

```bash
python scripts/build_standalone_visual_lab.py --output GlyphLock-Visual-Lab.html
```

The laboratory currently uses a tiny adapter with the same conceptual boundary as Pretext (`prepare` then `layout`). The actual Pretext dependency is deferred until the visual direction is approved; this keeps the first proof dependency-light and makes it easy to compare Pretext with native Android shaping later.

## Build the Android app

Requirements:

- JDK 21
- Gradle 9.4.1
- Android SDK 37

```bash
cd apps/android
gradle :app:testDebugUnitTest :app:lintDebug :app:assembleDebug
```

The debug APK is produced at:

```text
apps/android/app/build/outputs/apk/debug/app-debug.apk
```

The GitHub workflow provisions Gradle and the Android SDK and uploads the debug APK as an artifact. 
## Design review gate

Do not begin Hermes integration until the following are true:

1. The resting artwork is desirable with all event functionality disabled.
2. The transformation reads as one artwork changing state, not a notification overlay.
3. The final event state is readable in under two seconds.
4. The motion remains coherent on a physical Android device.
5. The wallpaper stops animation when hidden.
6. At least one scene is strong enough to serve as the project hero image without explanation.

See [Prototype 0 acceptance criteria](docs/PROTOTYPE_0.md).

## Generated artwork

The scene masks are original procedural assets generated by `scripts/generate_scene_masks.py`. Generated PNGs are deliberately excluded from source control and shared by the Android and browser builds through `assets/scenes/`. The user-provided reference images informed the desired density and level of detail, but they are not included or traced in this repository.
